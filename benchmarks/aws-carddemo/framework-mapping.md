# CardDemo -> Agentic Strangler Mapping

CardDemo is an external benchmark, so the framework should discover its structure rather than importing AtlasPay assumptions.

## UNDERSTAND

Collect evidence for:

- application entry points
- COBOL/program relationships
- CICS artifacts
- JCL/batch flows
- VSAM/data dependencies
- copybook/shared layouts
- assembler or other language dependencies
- optional Db2/IMS/MQ modules when present in the pinned upstream baseline
- tests/data/setup artifacts
- known unknowns

## DECIDE and later stages

Do not pre-select a modernization disposition for CardDemo in the benchmark harness. The first objective is to test whether the framework can construct evidence-backed understanding on an independently designed estate.

## Comparison discipline

If CardDemo is later analyzed with IBM Bob and AWS modernization tooling, compare dimensions such as evidence, completeness, planning, transformation boundaries, and human controls. Do not turn one sample into an unsupported vendor ranking.
